# UniShare Routing and Navigation Audit

Audit date: 2026-11-11

## Summary

- Inspected all 48 Razor view files, all 21 controller source files, `App_Start/RouteConfig.cs`, application startup, the shared layouts, and the 28 JavaScript files under `Scripts` (including vendor scripts). Static scanning found 159 view markup lines containing link or form declarations; dynamically generated controls were reviewed in the application scripts.
- Validated the 10 named friendly routes and the MVC 5 `{controller}/{action}/{id}` fallback against the controller/action declarations and view destinations referenced by the inspected navigation.
- Fixed 9 issue groups: user-page access control, admin access control, rental-request access control, the notification destination, admin dashboard shortcuts, verification AJAX URLs, admin sign-in landing, availability confirmation routing, and the duplicate rental CTA.
- Remaining issues are listed below. No browser-flow validation was possible in this pass.

## Fixes

| Page/component | Original issue | Fix |
| --- | --- | --- |
| Shared layout and `_Header` notification icon | The control in the active layout was a button with no loaded click handler or destination. | Made it an MVC-generated link to `Notifications/Index`; the action requires authentication. |
| User pages | Dashboard, listings, rentals, reports, sales, messages, notifications, and account settings could be opened directly without authentication. | Added MVC 5 `[Authorize]` checks at controller or action level. Existing `BorrowedItems` and verification restrictions remain in place. |
| Admin controllers | Admin dashboard, listing review, student review JSON actions, dispute management, and transaction records had no admin role authorization. | Added `[Authorize(Roles = "ADMIN")]` at controller level for those controllers and their data actions. |
| Browse item rental requests | GET/POST request actions and the compatibility POST were callable without a verified student session. | Added `[VerifiedStudent]` to all three actions. Changed the detail-page rental CTA to route to the request form only for verified users; unverified and anonymous users retain the verification or sign-in path. |
| Browse item availability modal | Confirming availability showed a success toast even though no rental request was sent. | Confirmation now navigates to the existing `BrowseItems/RequestToRent` form using a URL generated by `Url.Action()`. |
| Browse item details | The verified-user rental button was inert, and an extra rental link appeared for every user. The message button only showed a toast. | Replaced the inert rental button with the request-form link and removed the unconditional duplicate. The message control now opens the existing Messages page. |
| Admin dashboard | 13 shortcut/review controls only displayed “ready for backend integration” toasts. | Replaced them with links to existing student verification, item review, browse, rental, and dispute pages. Removed the placeholder toast handler. |
| Student verification page JavaScript | Approve/reject requests used root-relative hardcoded paths. | The view now supplies both URLs via `Url.Action()` data attributes, and the script reads those generated values. |
| Admin sign-in | Successful admin login went to the verification queue instead of the existing admin dashboard. | Redirects to `AdminDashboard/Index`; added an admin-only dashboard link to the shared navigation. |

## Route Configuration

`RouteConfig` defines named routes for Dashboard, BrowseItems, MyListings, MyRentals, BorrowedItems, SalesReport, Messages, Notifications, and Login, followed by the standard MVC 5 default route. Controller links also use the default route for pages without a friendly alias, including admin and verification pages. No duplicate route patterns or ASP.NET Core routing constructs were found.

## Remaining Issues and Limits

- The `AdminItemBookingController` data and approve/reject/delete actions are placeholders. Its JavaScript still marks rows changed locally and has TODO comments for persistence; a new page load restores sample rows.
- `AdminStudentVerificationController` returns sample students, and approve/reject actions return success without saving. The separate `Admin/StudentVerification` flow is the existing database-backed review path.
- `MyRentals`, `BorrowedItems`, dashboard data, dispute management, transaction records, and message interactions include sample or in-memory data/actions. Their navigation can open the intended screen, but changes are not established as durable database operations by this audit.
- `Scripts/availability.js` now opens the rental request form, but the selected calendar date is not carried into the form; the form maintains its own date selector.
- Several listing tabs, message-to-lender behavior, forgot-password, and admin detail actions remain prototype UI or lack complete backend behavior. They require product/backend implementation rather than additional route aliases.
- Browser tests and runtime route checks were not performed. The requested build was attempted with `dotnet build UniShare.sln --no-restore --configuration Debug` and could not run because the installed SDK lacks `Microsoft.WebApplication.targets` for this classic ASP.NET MVC 5 project. `msbuild` was not installed. `git diff --check` passed.
- `Web.config` was already modified before this audit and was left untouched.
